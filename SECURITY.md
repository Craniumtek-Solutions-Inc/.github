# Security Policy

Craniumtek Solutions Inc. takes responsible security reporting seriously.

## Reporting a vulnerability

Please **do not open a public GitHub issue** for suspected vulnerabilities, exposed credentials, authentication problems, privacy issues, or security-sensitive defects.

Send a private report to **admin@craniumtek.com** with the subject `Security Report` and include, where possible:

- affected repository, product, or URL;
- a concise description of the issue;
- reproduction steps or proof of concept that does not harm users or data;
- potential impact;
- suggested remediation, if known;
- your preferred contact details for follow-up.

Please avoid accessing, modifying, downloading, or retaining data that does not belong to you. Do not perform denial-of-service testing, destructive testing, social engineering, credential attacks, or actions that could disrupt production systems.

## Response process

We aim to acknowledge credible reports, assess severity and scope, contain immediate risk where necessary, remediate the issue, verify the fix, and coordinate disclosure when appropriate.

Repository-specific security policies may add stricter requirements and take precedence for that repository.

## Secrets

Never commit passwords, private keys, API tokens, certificates, production `.env` files, database dumps, customer information, or other sensitive material to source control.
