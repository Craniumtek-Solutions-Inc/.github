# Contributing to Craniumtek Projects

Thank you for your interest in contributing to Craniumtek Solutions Inc.

Not every repository in this organization accepts public contributions. Check the repository README and local contribution instructions first. Repository-specific rules take precedence over this organization default.

## Before opening work

1. Confirm the repository is intended for public collaboration.
2. Search existing issues and pull requests to avoid duplication.
3. For substantial changes, open an issue or discussion first unless the repository says otherwise.
4. Keep the proposed change narrowly scoped and explain the user or engineering problem it solves.

## Development expectations

Contributions should:

- preserve existing behavior unless the change intentionally modifies it;
- include tests or verification appropriate to the change;
- avoid secrets, production data, customer information, or private credentials;
- follow the repository's formatting, linting, security, and accessibility requirements;
- avoid adding unnecessary dependencies;
- document important architecture or operational changes;
- maintain clear trust boundaries between public applications, internal systems, and physical/industrial control systems.

## Pull requests

A good pull request should explain:

- what changed;
- why the change is needed;
- how it was tested;
- security, privacy, data, deployment, and rollback impact;
- screenshots or evidence when user-facing behavior changes.

Small, reviewable pull requests are preferred over unrelated bundles of changes.

## AI-assisted contributions

AI-assisted development is welcome when used responsibly. Contributors remain responsible for reviewing generated code, validating licenses and dependencies, protecting confidential information, testing behavior, and ensuring the final contribution meets the same standards as human-written code.

## Security issues

Do not submit vulnerabilities through public issues. Follow [`SECURITY.md`](SECURITY.md).

## Conduct

Participation is subject to [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).
